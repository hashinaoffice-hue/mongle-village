# handoff: 세션 인계

긴 대화를 계속 이어 가면 매 턴마다 앞의 기록 전체를 다시 읽기 때문에 토큰이 계속 늘어난다.
이 스킬은 작업 상태를 작은 파일 하나로 옮겨 두고, 대화를 비운 뒤 그 파일만 읽고 이어 가게 해서 이 비용을 줄인다.

먼저 사용자가 원하는 게 어느 쪽인지 판단한다.

- **저장**: 지금 세션을 마무리하고 인계 파일을 남기려는 경우 → 아래 "저장" 절차
- **이어 하기**: 새 세션에서 지난 작업을 이어 가려는 경우 → 아래 "이어 하기" 절차

## 저장

1. 대화 내용과 `git status`, `git diff --stat`, `git log --oneline -5`를 보고 현재 상태를 파악한다.
   이미 대화에 있는 정보는 다시 조사하지 않는다. 파일을 새로 여는 건 꼭 필요할 때만 한다.
2. 저장소 루트의 `HANDOFF.md`를 아래 형식으로 **덮어쓴다**. 이어 붙이지 않는다.
   파일이 길어지면 다음 세션에서 읽는 비용이 다시 커지기 때문이다. 60줄 이내를 목표로 한다.
3. 사용자에게 정리한 내용을 3~5줄로 요약해서 보여 준다.
4. 파일을 커밋할지 사용자에게 묻는다.
   클라우드 세션은 끝나면 컨테이너가 사라지므로, 커밋하고 푸시하지 않으면 다음 세션에서 HANDOFF.md를 볼 수 없다.
   사용자가 원하면 현재 브랜치에 커밋하고 푸시한다. 아직 커밋하지 않은 작업 코드가 있으면 그것도 함께 커밋할지 묻는다.
5. 마지막으로 다음 단계를 안내한다:
   "`/clear`로 대화를 비운 다음 `/handoff 이어서 하자`라고 입력하면 이어서 작업할 수 있어요."

### HANDOFF.md 형식

```markdown
# 작업 인계 (YYYY-MM-DD)

## 목표
지금 하고 있는 작업이 무엇이고 왜 하는지 1~2줄

## 완료한 것
- 무엇을 했는지 (관련 파일 경로)

## 결정한 것
- 고른 방식과 이유. 버린 방식이 있으면 왜 버렸는지도
  (다음 세션이 같은 고민을 반복하지 않게)

## 남은 일
1. 다음에 바로 할 일부터 순서대로
2. ...

## 주의할 점
- 알려진 버그, 아직 확인 못 한 것, 건드리면 안 되는 것

## 관련 파일
- `경로` : 한 줄 설명
```

다음 세션은 이 대화를 전혀 모르는 상태에서 이 파일만 읽는다는 점을 생각하며 쓴다.
"아까 말한 그 방식"처럼 대화를 봐야만 알 수 있는 표현 대신, 파일 경로와 함수 이름처럼 구체적으로 쓴다.
코드 전체를 붙여 넣지 말고 위치만 가리킨다. 코드는 다음 세션이 필요할 때 직접 열면 된다.

## 이어 하기

1. 저장소 루트의 `HANDOFF.md`를 읽는다. 없으면 사용자에게 알리고, `git log --oneline -10`으로 최근 작업을 짐작해서 보여 준다.
2. "남은 일"의 첫 항목과 "주의할 점"을 사용자에게 짧게 알려 주고, 그대로 진행할지 확인한다.
3. 작업을 시작할 때는 "관련 파일"에 적힌 파일만 먼저 연다.
   저장소 전체를 훑어보면 인계 파일을 만든 의미가 없어진다.
4. 작업이 끝나 가면 다시 "저장" 절차로 HANDOFF.md를 새로 쓴다.
